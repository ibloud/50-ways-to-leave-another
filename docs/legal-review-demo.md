# Legal Review Demonstration

**Version:** v1.0  
**Purpose:** educational case-study walkthrough  
**Status:** demonstration only — not an executed transaction

## What this demonstrates

This package lets a reviewer follow one hypothetical creative transaction across the connected repositories without treating the narrative, the DJ's workstation, or public availability as legal authorization.

### Demonstration chain

`Public signal → fictional DJ observation → PIXIE session → creative asset → contributor record → rights envelope → hypothetical agreement → delivery/release gate`

## Reviewer walk-through

### 1. Establish the world

The Story Lab defines a fictionalized narrative/evidence environment. Its source-status vocabulary separates documented material from attribution, interpretation, fiction, and unresolved questions.

**Review test:** Can a reader tell which parts are source-derived and which parts are invented?

### 2. Establish the operator

The social-network DJ is an in-world character. PIXIE Creator OS is the workstation she uses to prepare sets, manage creator workflow, and record session/object state.

**Review test:** Does the architecture avoid treating the software's existence as evidence that a person owns, authorized, or endorsed an asset?

### 3. Establish the artifact

A PIXIE object/session has a stable identifier and provenance trail. The object records workflow state; it does not decide copyright ownership.

**Review test:** Can the reviewer distinguish identity, presentation, implementation path, provenance, and ownership?

### 4. Establish contribution

If another person supplies lyrics, composition, performance, production, a beat, a sample, or other material, the contribution must be separately recorded and authorized.

**Review test:** Is pre-existing material distinguished from new work, and are contributors identified before a release claim is made?

### 5. Establish rights

The rights-control package separately addresses composition, master, performance, beat/instrumental, samples/interpolations, voice/likeness, AI output, and promotion/case-study use.

**Review test:** For each intended exploitation, can the reviewer identify the document that grants the required right?

### 6. Establish scope

For sync and master use, compare **media, territory, and term** independently. The usable scope is limited by the narrower grant.

**Review test:** Is streaming expressly covered? Are trailer, teaser, social, and advertising uses separately covered where needed?

### 7. Establish the deal boundary

A proposal, quote, public service listing, draft term sheet, or repository description is not silently upgraded into an accepted agreement.

**Review test:** Where are offer, acceptance, authority, consideration, rights grant, and signatures documented?

### 8. Establish release readiness

A missing or disputed right blocks distribution, licensing, pitching, or named case-study publication until resolved.

**Review test:** Is there a clear stop condition rather than an implied permission?

## Hypothetical legal-review matrix

| Issue | Demonstration evidence | If unresolved |
| --- | --- | --- |
| Authorship | Contribution record + split sheet | Do not state final ownership |
| Master | Signed production/collaboration agreement | Do not release the master |
| Performance | Performer consent/release | Do not distribute performance |
| Beat | License matching exact version and use | Replace or upgrade license |
| Sample/interpolation | Written clearance | Replace element or clear it |
| Voice/likeness | Specific written permission | Do not use publicly |
| AI | Tool/version/date/source/terms record | Review, disclose, or replace |
| Sync | Composition-side grant | Do not sync |
| Master use | Recording-side grant | Do not use recording |
| Streaming | Express SVOD/other applicable media | Do not assume coverage |
| Promotion | Express or separate promotional grant | Hold trailer/social/ad use |
| Case study | Separate named-use approval | Keep unnamed/private |
| Deal acceptance | Signed operative agreement | Treat as proposal only |
| Public endorsement | Direct documented authorization | Do not imply endorsement |

## Enforceability exercise

For educational review, convert the demonstration into a hypothetical operative deal by supplying the missing transaction facts:

1. legal names and capacity of all parties;
2. authority to sign;
3. exact services and deliverables;
4. payment and expense obligations;
5. acceptance/revision mechanics;
6. ownership or license language;
7. territory, media, and term;
8. contributor and third-party clearances;
9. publicity, credit, and case-study permissions;
10. representations/warranties and any negotiated indemnities;
11. termination and breach/cure provisions;
12. governing law, venue, dispute process, and remedies;
13. signatures and dated exhibits.

A reviewer should mark every field as **documented**, **proposed**, **missing**, or **not applicable**. No field should be treated as agreed merely because a plausible value can be invented for the demonstration.

## Reality boundary

This demonstration is deliberately conservative. It does not claim that a real collaborator accepted a proposal, that a public listing granted rights beyond its actual terms, that a platform integration is operational merely because it is designed, or that a Git commit creates an enforceable contract.

The purpose is to make those distinctions visible enough for a licensed attorney or other qualified reviewer to identify what would need to change before a real transaction could be executed.

## Interactive layer

An optional Ink or browser-based interactive map may visualize the same chain. It should remain a **navigation layer only** and link every legal/rights state back to its versioned source document.

Minimum stable behavior:

- works without authentication;
- works when external integrations are unavailable;
- exposes truth status at every node;
- exposes the current evidence/rights gate;
- never displays fictional approval as completed approval;
- never treats a PIXIE session as proof of ownership;
- links to the canonical continuity record and rights controls.
